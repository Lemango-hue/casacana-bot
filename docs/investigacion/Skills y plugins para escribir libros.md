# Las skills se instalan en Customize, no en Code

No ve ningún botón porque no existe: una sesión cloud de Claude Code no tiene navegador de plugins ni acepta el comando `/plugin`, y las skills se activan fuera de ella, en **claude.ai/customize/skills** (los plugins, en **claude.ai/customize/plugins**), desde donde se cargan solas en las sesiones cloud ([Claude Code: instalar plugins](https://code.claude.com/docs/en/discover-plugins), [Claude Code: skills](https://code.claude.com/docs/en/skills)). La segunda respuesta es menos cómoda: **Anthropic no publica ninguna skill ni plugin para escribir libros**, y lo mejor disponible a 23 de noviembre de 2026 son repositorios de terceros, casi todos de un solo autor. Tras leer sus archivos, los candidatos más sólidos son story-skills (el único con soporte documentado de español) y creative-writing-skills para ficción, APODICTIC como editor que diagnostica sin reescribir, y non-fiction-book-factory junto con Writing Desk para no ficción. Ninguno se probó escribiendo un libro, no se encontró ninguna reseña independiente de ellos, Reddit no fue accesible, y la única evaluación comparativa localizada dejó a tres de diez skills de ficción por debajo de no usar ninguna. Por eso lo que más pesa antes de la primera letra no se instala: lo escribe el autor (un acuerdo de reparto de trabajo, muestras de su propia prosa, una biblia del libro y un registro de estado) y condiciona incluso lo legal, porque Amazon KDP obliga a declarar el texto generado por IA aunque después se edite a fondo. Las recomendaciones cambian según el libro sea ficción o no ficción y según el idioma; cada apartado señala cuáles.

## Una sesión cloud no tiene navegador de plugins: todo se activa en Customize

La documentación es explícita: una sesión cloud, incluida la de claude.ai/code, «no tiene navegador de plugins» y no carga los plugins instalados en un ordenador ([instalar plugins](https://code.claude.com/docs/en/discover-plugins)); los comandos que solo funcionan en terminal, como `/plugin`, tampoco están disponibles en la web ni en la app móvil ([Claude Code en la nube](https://code.claude.com/docs/en/claude-code-on-the-web), [Claude Code en móvil](https://code.claude.com/docs/en/mobile)). La ausencia del botón es diseño, no un fallo de la cuenta. A cambio, la sesión cloud carga «sin ninguna configuración» las skills activadas en la cuenta de claude.ai, que se gestionan en la página **Customize** de la barra lateral de claude.ai o de la app de escritorio, fuera de la pantalla de Code ([skills en sesiones cloud](https://code.claude.com/docs/en/skills), [visión general de skills](https://claude.com/docs/skills/overview)).

El camino tiene tres pasos, todos leídos en la documentación vigente. Primero, en Settings > Capabilities debe estar activado «Code execution and file creation» (llamado «Create and edit files» en el diseño nuevo). Segundo, en **Customize > Skills** se activa cada skill con su interruptor, o se añade una del directorio con «+» > «Browse skills» > «Add». Tercero, una skill descargada de GitHub se sube como ZIP con «+» > «+ Create skill» > «Upload a skill» ([Centro de ayuda: usar skills](https://support.claude.com/en/articles/12512180-using-skills-in-claude), [Centro de ayuda: directorio, 25-sep-2026](https://support.claude.com/en/articles/14328846-browse-skills-connectors-and-plugins-in-one-directory)). El ZIP debe llevar la carpeta de la skill en su nivel superior, porque un `SKILL.md` suelto en la raíz no se reconoce, y el nombre de la carpeta debe coincidir con el campo `name` ([crear skills](https://claude.com/docs/skills/how-to)). Los plugins siguen la misma lógica en **Customize > Plugins > Discover > Add**; la misma página admite un repositorio de terceros con Add > «Add marketplace» (se escribe `autor/repositorio`) y solo existe en planes de pago ([plugins](https://claude.com/docs/plugins/overview), [Centro de ayuda: plugins](https://support.claude.com/en/articles/13837440-use-plugins-in-claude)). Conviene saber qué llega a cada superficie: en el chat un plugin solo aporta sus skills, comandos y conectores, mientras que sus agentes y hooks se ignoran allí y sí cargan en Cowork y Claude Code ([compatibilidad por plataforma](https://claude.com/docs/plugins/platform-support)).

Dentro de la sesión hay dos vías más. Claude puede mostrar una tarjeta de sugerencia de plugins con un botón **Add**, que activa el plugin en la cuenta de forma permanente ([Claude Code en la nube](https://code.claude.com/docs/en/claude-code-on-the-web)). Y una skill guardada en la carpeta `.claude/skills/` de un repositorio viaja con el clon, a diferencia de la carpeta personal `~/.claude/skills/`, que no llega a la nube ([entornos cloud](https://code.claude.com/docs/en/cloud-environments)). Esta segunda vía importa por otra razón: la máquina de una sesión cloud es desechable. Se pausa tras unos minutos sin actividad y una máquina pausada puede reclamarse; cuando eso ocurre, al reabrir se aprovisiona una máquina nueva y solo se restaura el historial de conversación ([entornos cloud](https://code.claude.com/docs/en/cloud-environments), [Claude Code en la nube](https://code.claude.com/docs/en/claude-code-on-the-web)). Una observación directa de esta sesión, que no es una fuente publicada, lo vuelve urgente: **no hay ningún repositorio adjunto**. De ahí se deduce que un manuscrito escrito aquí sin repositorio no tiene garantía de persistir, así que el libro debe vivir en un repositorio de GitHub (o en un Project de claude.ai) antes de empezar. La misma observación mostró que la cuenta ya tiene sincronizadas 23 skills, entre ellas `skill-creator`, `docx`, `pdf` y `doc-coauthoring`, y cuatro plugins.

Cuatro puntos quedan sin verificar o en conflicto. Los nombres de menú se dan en inglés, como aparecen en la documentación; no se comprobó cómo se llaman en la interfaz en español. Ninguna página describe una pantalla Customize en la app móvil, de modo que si la sesión se abrió desde el teléfono lo seguro es entrar a claude.ai/customize/skills desde un navegador. Tampoco está documentado cuánto tarda una skill recién activada en aparecer en una sesión ya abierta; lo prudente es iniciar una sesión nueva. Y las fuentes oficiales se contradicen dos veces: el Centro de ayuda incluye el plan Free entre los que tienen skills, mientras que las otras dos páginas de documentación solo citan planes de pago ([Centro de ayuda](https://support.claude.com/en/articles/12512180-using-skills-in-claude), [visión general](https://claude.com/docs/skills/overview)); y la página de plataforma afirma que las skills propias no se sincronizan entre superficies, cosa que desmienten la documentación de Claude Code y lo observado en esta sesión ([plataforma](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview), [skills](https://code.claude.com/docs/en/skills)). Además, la referencia de carga de plugins solo nombra Cowork y la terminal como destino de los plugins sincronizados ([carga de plugins](https://code.claude.com/docs/en/plugins/loading)); que lleguen a las sesiones cloud consta por observación, no por documento.

Sobre seguridad, Anthropic pide tratar una skill como software: usar solo las propias o las de Anthropic y auditar todas las demás antes de activarlas ([seguridad de skills](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)). Los plugins del directorio pasan validación automática, escaneo y revisión humana de cada alta, pero esa revisión no cubre lo que se añade por URL o se sube a mano ([plugins](https://claude.com/docs/plugins/overview)), y un plugin de Claude Code puede ejecutar código arbitrario con los permisos del usuario ([seguridad de plugins](https://code.claude.com/docs/en/plugins/security)). Todo lo que sigue en este informe es de terceros, así que esa cautela se aplica entero. Las skills hechas solo de Markdown, sin carpeta de scripts, son las más fáciles de revisar.

### Si el libro es ficción

**story-skills** es la base de proyecto mejor fundada. Guarda la biblia de la historia en Markdown y la somete a un comprobador que no depende del modelo: detecta personajes muertos que reaparecen, desenlaces anteriores a su planteamiento y quién sabe qué desde qué capítulo ([README](https://github.com/danjdewhurst/story-skills/blob/main/README.md)). Su skill de capítulos exige que el autor apruebe el esquema antes de la prosa ([chapter-writing](https://github.com/danjdewhurst/story-skills/blob/main/skills/chapter-writing/SKILL.md)). La justificación del diseño es una tesis de su autor, sin pruebas comparativas: la coherencia a larga distancia es lo que peor hacen los modelos y no se arregla con instrucciones ([blog del autor](https://ddewhurst.com/blog/story-skills-continuity-compiler-for-ai-fiction/)). **creative-writing-skills** tiene el mejor texto de oficio de los leídos: explica por qué los hábitos conversacionales del modelo dañan la ficción y trata distancia psíquica, estilo indirecto libre y ritmo con ejemplos ([writing-principles](https://github.com/haowjy/creative-writing-skills/blob/main/plugin/claude/skills/writing-principles/SKILL.md)). Su preparación entrevista al autor y recoge muestras de su prosa ([README](https://github.com/haowjy/creative-writing-skills/blob/main/README.md)). Cada uno define su propio formato de proyecto y no hay documentación de interoperabilidad, de modo que conviene elegir uno como columna vertebral y no mezclar.

Para crítica sin reescritura, **APODICTIC** infiere el «contrato» del manuscrito (género, promesa al lector) y lo mide en once pasadas, con seguimiento de continuidad entre volúmenes de una serie ([README](https://github.com/anotherpanacea-eng/apodictic/blob/main/README.md)); publica una carta editorial de muestra que se puede leer sin instalar nada ([muestra](https://anotherpanacea-eng.github.io/apodictic/sample-editorial-letter.html)). Calliope ofrece crítica equivalente en Markdown puro, la opción de menor riesgo técnico.

La generación autónoma «de la idea al libro» es la apuesta más débil, y lo dicen sus propios autores. Book Genesis reporta que un borrador completo de 24 capítulos y 83.517 palabras obtuvo 72,52 sobre 100 en su evaluación automática sin superar sus propios umbrales de calidad, y que todos los casos documentados son del mantenedor ([README](https://github.com/felipelobomotta-blip/book-genesis-studio/blob/master/README.md)). El autor de fiction-forge cuenta que una sola lectura secuencial con libro de estado encontró **191 fallos reales que cinco pasadas editoriales automáticas habían dejado pasar**, y que los consejos genéricos contra la «prosa de IA» alejaron el texto del estilo buscado ([README](https://github.com/geobond13/fiction-forge/blob/main/README.md)). Son autoinformes no verificables, pero apuntan en la misma dirección.

### Si el libro es no ficción

No existe un equivalente de story-skills. **non-fiction-book-factory** cubre ideación, validación, arquitectura y un esquema de capítulo detallado, y termina justo antes de redactar; delega la ejecución de la investigación en herramientas externas, y el mismo repositorio trae aparte una skill de captura de voz por entrevista ([README](https://github.com/robertguss/claude-code-toolkit/blob/HEAD/skills/non-fiction-book-factory/README.md)). Su licencia es ambigua: el repositorio declara MIT y las skills declaran «Proprietary» ([LICENSE](https://github.com/robertguss/claude-code-toolkit/blob/HEAD/LICENSE.md), [chapter-architect](https://github.com/robertguss/claude-code-toolkit/blob/HEAD/skills/non-fiction-book-factory/chapter-architect/SKILL.md)). **Writing Desk** aporta la disciplina de edición más útil para un texto con datos: nada se inventa, cada cambio aparece en una tabla con su motivo, los huecos se marcan y no se endurecen matices ni se redondean cifras ([write-edit](https://github.com/najikay/claude-writing-desk/blob/HEAD/skills/write-edit/SKILL.md)). Su autor publica 116 comprobaciones superadas de 117 con el plugin frente a 55 sin él, medidas por él mismo con un modelo como juez ([README](https://github.com/najikay/claude-writing-desk/blob/HEAD/README.md)).

El motor de no ficción de APODICTIC solo cubre formas argumentativas (artículo de opinión, informe de políticas, argumento académico, libro blanco y similares); las memorias y la divulgación narrativa quedan fuera de ese alcance declarado ([nonfiction-argument-engine](https://github.com/anotherpanacea-eng/apodictic/blob/HEAD/plugins/apodictic/skills/nonfiction-argument-engine/SKILL.md)). La verificación de hechos merece una pasada aparte: la skill `fact-check` de jwynia sostiene que no se combina de forma fiable con la generación en una sola pasada; el repositorio lleva sin commits desde febrero de 2026, aunque son instrucciones en texto sin dependencias ([fact-check](https://github.com/jwynia/agent-skills/blob/HEAD/skills/general/research/verification/fact-check/SKILL.md)). No se encontró ninguna skill pública que convierta entrevistas o transcripciones en capítulos.

De los plugins de escritura del directorio de claude.ai, lo aprovechable son métodos sueltos. Writing With Agents separa generar, estructurar, redactar y juzgar, con el autor al mando de la estructura; su rúbrica define tipos como documentación técnica, post y artículo SEO, pero no libro ni capítulo ([README](https://github.com/Jeffallan/writing-with-agents/blob/HEAD/README.md), [umbrales](https://github.com/Jeffallan/writing-with-agents/blob/HEAD/plugin/skills/quality-rubric/references/minimum-standards.md)). Online Writing se declara a sí mismo limitado a escritura «social» de posts y artículos ([README](https://github.com/DonHeidi/online-writing-skills/blob/HEAD/README.md)). Otros dos plugins que devolvió la consulta al catálogo de la cuenta, writing-quality y Writing Intelligence Studio, no tienen repositorio público localizable; no se leyeron y no se valoran aquí. Ese dato procede de la búsqueda interna del catálogo, que carece de URL pública.

### Si el libro es en español

El idioma descarta más opciones que el género. **story-skills es el único proyecto con soporte explícito**: declara listas completas de palabras para español, parte el manuscrito por «Capítulo» y documenta la raya de diálogo y los signos de apertura, aunque avisa de que su consejo de oficio está escrito para el inglés ([idiomas](https://github.com/danjdewhurst/story-skills/blob/main/docs/languages.md)). En creative-writing-skills, APODICTIC y Calliope el español no se menciona; que funcionen bien con un manuscrito en español es una suposición sin probar. Los proyectos nativos en español existen, pero todos tienen cero estrellas y meses o días de vida: PUBIA es el único con criterio editorial propio del idioma (concordancia, variedad regional, formas orales que no se corrigen) ([README](https://github.com/grananda/pubia/blob/main/README.md)); Forja está pensado primero para otra herramienta y no tiene licencia ([README](https://github.com/KolonLabs/forja/blob/main/README.md)).

El choque más concreto está en las pasadas «anti-IA». Las dos skills con más estrellas, humanizer y stop-slop, ordenan eliminar las rayas, y humanizer convierte además las comillas tipográficas en rectas ([humanizer](https://github.com/blader/humanizer/blob/HEAD/SKILL.md), [stop-slop](https://github.com/hardikpandya/stop-slop/blob/HEAD/SKILL.md)). En español, en cambio, la raya precede cada intervención de un diálogo y enmarca los incisos del narrador, y la jerarquía de comillas empieza por las angulares ([Ediciones Complutense](https://www.ucm.es/ediciones-complutense/signos-ortotipograficos)). La única prueba independiente con textos en español, sobre dos textos cortos en español y uno en inglés y con un modelo como juez, concluyó que las listas de palabras vetadas son inglesas y que solo los patrones de estructura viajan entre idiomas; dio a no-ai-slop 67 puntos de 75 frente a 49 de stop-slop ([Web Reactiva, 20-oct-2026](https://www.webreactiva.com/blog/comparativa-skills-anti-slop)). No se encontró ninguna skill pública de ortotipografía española, y la adaptación al español de avoid-ai-writing figura solo como «planeada» ([README](https://github.com/jurigis/avoid-ai-writing-multilingual/blob/HEAD/README.md)). La consecuencia práctica es que **la pieza más valiosa para un libro en español hay que construirla**: una skill propia con la hoja de estilo, las muletillas en español y las reglas de raya y comillas, hecha con `skill-creator`, que además permite evaluar la skill con pruebas ([skill-creator](https://github.com/anthropics/skills/blob/HEAD/skills/skill-creator/SKILL.md)). Si el libro fuera en inglés, estas restricciones desaparecen y casi todo el catálogo se aplica tal cual.

### Una sola pasada «anti-IA», y con cautela

La popularidad de estas skills no demuestra eficacia. El propio README de humanizer admite que los detectores siguen marcando la mayor parte de su salida ([README](https://github.com/blader/humanizer/blob/HEAD/README.md)). El estudio que respalda su cifra de «16 de 16» usó modelos como jueces, y midió que el vocabulario típico de IA bajó de 70 a 0 mientras los tics de ritmo subieron de 60 a 101 ([issue 229](https://github.com/blader/humanizer/issues/229)). Su versión 4.0.0 revirtió la regla de no inventar y ahora añade detalles concretos cuando el texto es genérico, un riesgo directo para la no ficción ([CHANGELOG](https://github.com/blader/humanizer/blob/HEAD/CHANGELOG.md)). Acepta, eso sí, una muestra de la prosa del autor que prevalece sobre sus reglas, incluida la de las rayas ([SKILL.md](https://github.com/blader/humanizer/blob/HEAD/SKILL.md)). No existe ninguna evaluación con lectores humanos ni sobre capítulos completos. La posición razonable es usar una sola, primero en modo detección, con muestra de voz, y nunca apilar varias.

### Producción y lo que conviene evitar

Para entregar el manuscrito, la skill oficial `docx` crea y edita Word con control de cambios y valida que ningún cambio quede sin marcar ([docx](https://github.com/anthropics/skills/blob/HEAD/skills/docx/SKILL.md)). Las dos skills que intentan la producción completa para KDP llevan siete u ocho meses sin commits; la plantilla de impresión de kindle-book-skill no carga los paquetes de idioma de LaTeX, y bullpen revisa la prosa con reglas inglesas ([plantilla](https://github.com/nikmcfly/kindle-book-skill/blob/HEAD/assets/print-template.tex), [bullpen](https://github.com/benhowdle89/bullpen/blob/HEAD/.vale.ini)). Sirven como plantilla que adaptar; la base fiable es pandoc, que toma el idioma de la variable `lang` y admite un documento de referencia de estilos para Word ([manual de pandoc](https://pandoc.org/MANUAL.html)). No se comprobó el resultado real de pandoc con español.

Hay recursos que evitar. El repositorio denidelapan7/longform-claude-extension imita el nombre de un plugin legítimo y solo contiene marketing y un botón de descarga, sin ninguna skill; la calificación de señuelo se basa en su estructura, no en un análisis de la descarga ([repositorio](https://github.com/denidelapan7/longform-claude-extension)). El plugin redliner descarga e instala un binario mediante un hook ([repositorio](https://github.com/tcotav/redliner)). storyforge tiene licencia solo para uso no comercial ([README](https://github.com/markus-michalski/storyforge/blob/main/README.md)), y howells/fiction, pese a su actividad, no tiene licencia ([repositorio](https://github.com/howells/fiction)). Los proyectos con más estrellas de la categoría, con más de 8.000, pertenecen al ecosistema chino de novela web y no encajan por idioma ni por convenciones ([oh-story](https://github.com/zenstory-ai/oh-story-claudecode)).

## El autor decide primero quién escribe las frases: de ahí salen la calidad y la situación legal

La decisión de mayor alcance es el reparto de trabajo, y tiene consecuencias legales distintas según la respuesta. Amazon KDP define como «generado por IA» todo texto creado por la herramienta **aunque después se le apliquen ediciones sustanciales**, y exige declararlo; el texto escrito por el autor y luego editado, corregido o mejorado con IA es «asistido» y no requiere declaración ([directrices de KDP](https://kdp.amazon.com/en_US/help/topic/G200672390)). La Oficina de Copyright de Estados Unidos concluye que usar IA como asistente no afecta a la protección, que el material puramente generado no es protegible y que los prompts por sí solos no dan control suficiente; reconoce autoría sobre la selección, la ordenación y las modificaciones creativas de las salidas ([informe, parte 2](https://www.copyright.gov/ai/Copyright-and-Artificial-Intelligence-Part-2-Copyrightability-Report.pdf)). Las dos categorías no coinciden: un flujo «Claude redacta y el autor edita mucho» obliga a declarar en KDP y a excluir ese contenido al registrar la obra, mientras que «el autor redacta y Claude critica y corrige» no obliga a nada y deja el copyright intacto ([guía de registro](https://www.copyright.gov/ai/ai_policy_guidance.pdf)). La Authors Guild añade que incluir texto generado puede incumplir la garantía de originalidad de un contrato editorial y recomienda avisar al editor y declarar a los lectores cualquier uso sustancial ([Authors Guild, 11-may-2026](https://authorsguild.org/resource/ai-best-practices-for-authors/)).

Todo eso es derecho y práctica de Estados Unidos, y es información, no asesoramiento jurídico. El marco de España y de Latinoamérica no se verificó en fuentes primarias. En la Unión Europea, el artículo 50 del Reglamento de IA impone divulgar el texto generado que se publica para informar sobre asuntos de interés público, salvo que haya pasado por revisión humana con responsabilidad editorial ([artículo 50](https://artificialintelligenceact.eu/article/50/)); que una novela o un ensayo firmado queden fuera es una interpretación razonable, no un criterio oficial. Los términos de consumo de Anthropic ceden al usuario los derechos que Anthropic tuviera sobre las salidas, «si los hubiera», lo que no crea copyright donde la ley no lo reconoce ([términos de consumo](https://www.anthropic.com/legal/consumer-terms)). Antes de subir el manuscrito conviene revisar el ajuste de cuenta que permite usar las conversaciones para mejorar los modelos ([centro de privacidad](https://privacy.claude.com/en/articles/10023580-is-my-data-used-for-model-training)).

Los relatos de primera mano favorecen el mismo reparto por razones de calidad. Una autora que llevó una trilogía de más de 100.000 palabras en un Project prohíbe por escrito que Claude redacte su prosa y juzga la imitación de su estilo útil para idear, pero no publicable ([Your Creative Edge](https://yourcreativeedge.substack.com/p/using-claude-for-long-form-fiction)). Robert Matsuoka, que alimentó al modelo con cuatro años de textos propios y una guía de estilo de más de 3.000 palabras, concluye que el sistema produce escritura aceptable, no buena, con cerca de un 30 % de intervención humana ([HyperDev, 30-dic-2025](https://hyperdev.matsuoka.com/p/the-acceptable-writing-machine-building)). En no ficción, Fei Wu hizo cotejar 870 afirmaciones con sus fuentes: 446 se corrigieron y 293 se borraron por inverificables, y aun así el modelo dio cinco veces mal el recuento central del libro y sobrescribió un archivo fuente ([Feisworld](https://www.feisworld.com/blog/the-ai-was-confidently-wrong-about-the-most-important-number-in-my-book-five-times)). Son casos individuales, varios de ellos en boletines con interés comercial; no hay datos cuantitativos.

De esas fuentes sale lo que el autor necesita tener escrito antes de empezar; la lista y su orden son síntesis de este informe. Un acuerdo de colaboración que diga qué hace Claude y qué no. Una ficha del libro con premisa, lector, promesa, extensión, punto de vista y tono. Un corpus de voz con muestras reales de su prosa. Una biblia separada del manuscrito: personajes, mundo y cronología en ficción; registro de fuentes con cada afirmación trazada a su origen en no ficción. Un registro de estado y de decisiones que se actualiza tras cada capítulo, porque los autores coinciden en que el método falla cuando se omite esa actualización. Control de versiones y copias fuera del alcance de la herramienta. Un registro de qué pasajes generó la IA, que sirve a la vez para KDP, el copyright y la editorial. Y, si el libro es en español, una hoja que fije la variedad regional, el tratamiento y la ortotipografía. Anthropic reconoce en sus términos que las salidas pueden contener inexactitudes aunque parezcan precisas ([términos de consumo](https://www.anthropic.com/legal/consumer-terms)); la verificación final de hechos es del autor.

## Claude rinde con contexto en archivos y pocas reglas, no con prompts mágicos

Los repositorios de prompts son la parte más floja de lo pedido. Anthropic ya no publica su biblioteca de prompts: las direcciones antiguas, incluida la del prompt de narrativa, redirigen a una única página viva de buenas prácticas, y no existe ninguna guía oficial de ficción ni de libros ([buenas prácticas](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices), [índice de la documentación](https://platform.claude.com/llms.txt)). La mayor colección comunitaria, prompts.chat, tiene 178.000 estrellas y un prompt de «novelista» del patrón «actúa como», sin contexto ni voz del autor ([prompts.chat](https://github.com/f/prompts.chat)). Los generadores de novelas que fueron populares llevan parados desde 2024 o 2025 y apuntan a modelos de entonces ([gpt-author](https://github.com/mshumer/gpt-author)). El sistema de prompts mejor diseñado que se leyó, StoryEngine, tiene cero estrellas: guarda el estado en archivos, exige aprobación del autor en cada fase y simula un lector que no ve las notas ([StoryEngine](https://github.com/brian-caylor/StoryEngine_Template)). En español lo más aprovechable es un archivo de instrucciones de un solo autor, con una estrella y escrito para otro modelo, que pide diagnóstico «sin adulación» y respeto por la voz ([gemini-novel-craft](https://github.com/Rodryy-dev/gemini-novel-craft)). En este nicho las estrellas no señalan calidad.

Lo que Claude necesita está en la guía oficial, y contradice buena parte de los prompts que circulan. Los documentos largos van arriba y la petición al final, lo que en las pruebas de Anthropic mejora la respuesta hasta un 30 %. Los ejemplos son de lo más fiable para dirigir tono y estructura: de tres a cinco, variados y entre etiquetas. Las instrucciones rinden más con su porqué y en positivo, y el estilo del propio prompt contagia la salida ([buenas prácticas](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)). Con los modelos actuales, las listas de prohibiciones perjudican: Fable 5.2 sigue las reglas de estilo tan de cerca que un límite rígido vuelve la prosa entrecortada, trata como absoluta cualquier instrucción con «nunca», y su esfuerzo recomendado de partida es `high` ([guía de Fable 5.2](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-2)). Aquí hay una tensión real con los practicantes, que mantienen listas de palabras vetadas. Se resuelve usando la lista como comprobación posterior, por búsqueda, y no como instrucción.

El resto son hechos técnicos sobre la memoria. Los modelos actuales tienen una ventana de un millón de tokens, unas 555.000 palabras según Anthropic, así que un manuscrito entero cabe ([modelos](https://platform.claude.com/docs/en/about-claude/models/overview)). El cuello de botella es otro: **cada sesión de Claude Code empieza con el contexto en blanco** y solo arrastra el archivo `CLAUDE.md`, que debe quedar por debajo de 200 líneas, y la memoria automática ([memoria](https://code.claude.com/docs/en/memory)). Cuando la conversación se compacta, lo dicho solo en el chat se pierde, se releen como máximo cinco archivos, y uno de más de 5.000 tokens vuelve solo como referencia de ruta ([ventana de contexto](https://code.claude.com/docs/en/context-window)). De ahí la forma del proyecto: un `CLAUDE.md` corto con las reglas de voz y el ritual por capítulo, archivos pequeños de biblia, estado y resúmenes, una sesión por capítulo, y la comprobación de continuidad en un subagente de solo lectura, cuyo límite lo impone la herramienta y no una petición ([buenas prácticas de Claude Code](https://code.claude.com/docs/en/best-practices)). En claude.ai el equivalente es un Project por libro, con memoria propia y hasta 30 MB por archivo ([Projects](https://support.claude.com/en/articles/9517075-what-are-projects), [memoria](https://support.claude.com/en/articles/11817273-using-claude-s-chat-search-and-memory-to-build-on-previous-context), [límites de archivos](https://support.claude.com/en/articles/8241126-what-kinds-of-documents-can-i-upload-to-claude)).

Dos precisiones para el español. Anthropic publica que sus modelos rinden en español entre el 98 % y el 99,8 % de su nivel en inglés, pero en una prueba de conocimiento y razonamiento, no de calidad literaria; recomienda declarar de forma explícita el idioma de salida ([soporte multilingüe](https://platform.claude.com/docs/en/build-with-claude/multilingual-support)). No se encontró ninguna evaluación independiente de la prosa literaria en español de estos modelos. Y las estructuras narrativas clásicas (Save the Cat, el viaje del héroe, el método del copo de nieve) rinden más como rúbrica para diagnosticar el esquema del autor que como molde para generar; basta nombrarlas, porque los modelos ya las conocen y varias son marcas con derechos reservados ([Save the Cat](https://savethecat.com/get-started), [método Snowflake](https://www.advancedfictionwriting.com/articles/snowflake-method/)).

## Dónde la evidencia es débil y las fuentes se contradicen

Ninguna skill se instaló ni se ejecutó. Todos los juicios de calidad de este informe son sobre el texto de los archivos, y la lectura fue parcial: 2 de las 24 skills de story-skills, 3 de las 25 de creative-writing-skills. Ningún script se auditó línea por línea; las búsquedas de llamadas de red fueron por patrón. Nadie comprobó cómo se comporta ninguna de estas skills con un manuscrito en español.

No se encontró ninguna reseña independiente de usuarios de ningún sistema de escritura de novelas, ni comparación externa entre ellos. **Reddit no fue accesible** desde las herramientas de investigación, así que este informe no atribuye nada a r/ClaudeAI ni a r/WritingWithAI; las búsquedas en Hacker News sobre estos proyectos no devolvieron hilos. Casi toda la evidencia de calidad es autoinforme de los mantenedores. Las señales de popularidad engañan: en skills.sh, un repositorio de tres estrellas y un solo commit acumula 2.273 instalaciones ([skills.sh](https://skills.sh/api/search?q=novel&limit=30)), y el directorio de claude.ai no devolvió cifras de instalación. La única evaluación comparativa hallada es de alcance mínimo: diez skills de ficción más un control sin skill, solo sobre premisas, con un único modelo; el control quedó noveno, con tres skills por debajo, y los dos jueces discreparon en 63 de 198 comparaciones ([awesome-novel-skills](https://github.com/UnderleveledBuilder/awesome-novel-skills/blob/main/README.en.md)). Demuestra que una skill puede empeorar el resultado, y poco más.

Hay un conflicto sin resolver sobre APODICTIC. Su README afirma que está en el directorio de plugins de Claude. Una comprobación no lo encontró en el marketplace oficial ni en su dirección pública, que devolvió un error 404; otra lo obtuvo de la consulta al catálogo de la cuenta. La documentación explica que el directorio de claude.ai y los marketplaces de Claude Code son catálogos distintos ([marketplaces de Anthropic](https://code.claude.com/docs/en/plugins/anthropic-marketplaces)), lo que haría compatibles ambos resultados; se confirma en un minuto mirando Customize > Plugins > Discover. Por el mismo motivo, la frase «no hay plugins de ficción» vale para el marketplace oficial; el listado completo del directorio no pudo leerse.

Varias citas requieren cotejo antes de reproducirse. El sitio de la RAE bloqueó la lectura directa, así que las normas de raya y comillas se citan a través de Ediciones Complutense. Las citas de páginas ajenas a Anthropic y a GitHub pasaron por una herramienta que resume y a veces recorta. No se leyeron en fuente primaria la situación legal en España y México ni las políticas de editoriales en español. Tampoco hay ningún estudio que compare, en libros completos, el borrador humano primero frente al borrador de IA primero.

## Conclusión

El hallazgo que ordena todo lo demás es una inversión: las skills que mejor resisten la lectura son las que restringen a Claude (no reescribir, no inventar, mostrar cada cambio, esperar la aprobación del autor), y las que generan capítulos enteros son las que sus propios autores no avalan. «Lo mejor de lo mejor» resulta ser, por tanto, un conjunto pequeño: lo que la cuenta ya tiene (`skill-creator`, `docx`, `doc-coauthoring`), un sistema de proyecto elegido según el género, un editor que diagnostique, y una skill propia en español que nadie ha publicado todavía. Instalar más añade superficie de riesgo y reglas que se pisan entre sí, sin evidencia de que mejore el libro.

Antes de instalar nada quedan tres decisiones que este informe no puede tomar. Ficción o no ficción determina el sistema de proyecto. El idioma determina cuánto del catálogo sirve sin adaptación. Y quién redacta las frases que se publicarán determina la declaración ante KDP, el alcance del copyright y, según los testimonios, la calidad. Con esas tres respuestas, el primer paso práctico no es una instalación: es crear un repositorio para el libro, porque la sesión cloud actual no conserva archivos por sí misma, y dentro de él pueden vivir tanto el manuscrito como las skills.
